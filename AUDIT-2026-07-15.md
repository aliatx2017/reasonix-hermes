## 1. Critical Bugs

### 1.1 MCP Bridge: `reasonix_run` Command Injection (HIGH)

**File:** `cmd/reasonix-mcpbridge/main.go:164-169`

```go
cmd := exec.CommandContext(ctx, "reasonix", args...)
cmd.Dir = workdir
cmd.Env = os.Environ()
```

`task` string flows directly from MCP client input into `exec.Command` arguments. No sanitization. A malicious MCP client sending `task: "foo'; rm -rf /"` would pass it verbatim. While `exec.Command` doesn't shell-expand, the `model` and `workdir` parameters also lack validation — `workdir` could point to `/` or `/etc`.

**Fix:** Validate `workdir` resolves inside allowed paths. Sanitize `task` for shell metacharacters if ever used in shell context. Add `--` separator before task args.

### 1.2 MCP Bridge: Hardcoded API Key in `doctorCheck` (MEDIUM)

**File:** `cmd/reasonix-mcpbridge/main.go:192-193`

```go
if key := os.Getenv("DEEPSEEK_API_KEY"); key != "" {
    report.WriteString("✅ **DEEPSEEK_API_KEY**: Set (length: " + fmt.Sprintf("%d", len(key)) + " chars)\n")
```

Reveals key length. An attacker can brute-force character-by-character with length oracle attacks. Also, `callDeepSeek` at line 325 sends the key as `Authorization: Bearer` + key in cleartext — fine over HTTPS, but `doctorCheck` output could be logged/returned to untrusted callers.

**Fix:** Replace length disclosure with `"Set (8+ chars)"` or just `"Set"`. Don't expose key length.

### 1.3 Memory Server: Data Race in `SearchDense` (HIGH)

**File:** `cmd/reasonix-memoryserver/main.go:199-246`

`SearchDense` acquires `ms.mu.Lock()` (exclusive), but `SearchSimilar` acquires `ms.mu.RLock()`. Both methods iterate and copy `ms.entries`. If `Retain` (which holds `ms.mu.Lock()`) runs concurrently with `SearchSimilar` (which holds `ms.mu.RLock()`), the RLock is correct. But `SearchDense` acquires exclusive lock when it only reads — it should use `RLock`. This blocks all concurrent reads during dense search.

**Fix:** Change `SearchDense` to use `ms.mu.RLock()` + `defer ms.mu.RUnlock()`, same as `SearchSimilar`.

### 1.4 Memory Server: Importance Decay Resets CreatedAt (MEDIUM)

**File:** `cmd/reasonix-memoryserver/main.go:286-292`

```go
days := now.Sub(e.CreatedAt).Hours() / 24
e.Importance = max(0, e.Importance-importanceDecayPerDay*days)
e.CreatedAt = now // reset anchor so we don't double-decay
```

`CreatedAt` is overwritten with `now` during `Tidy()`. This destroys the original creation timestamp, which is used for display (`Reflect` shows `e.CreatedAt.Format("Jan 2 15:04")`). After one tidy pass, all memories show today's date instead of when they were actually created.

**Fix:** Add a separate `LastDecayAt` field. Decay based on `now - LastDecayAt`, not `now - CreatedAt`. Preserve `CreatedAt` for display.

### 1.5 Memory Server: Recall Modifies State Under Read Lock (MEDIUM)

**File:** `cmd/reasonix-memoryserver/main.go:343-416`

`Recall` holds `ms.mu.Lock()` and mutates entries (increments `AccessCount`, boosts `Importance`, extends `ExpiresAt`, then calls `ms.save()`). This means a recall query permanently modifies data — read operations should not have write side effects. More critically, the save-on-every-recall pattern creates write amplification: every search writes the entire JSON file.

**Fix:** Separate read-path (search, no mutation) from write-path (periodic `Tidy` that handles importance decay and access count flushes). Or batch mutations and flush on `Tidy` instead of on every recall.

### 1.6 Collab Hub: No Write Deadline on WebSocket Messages (MEDIUM)

**File:** `internal/collab/collab.go`

WebSocket writes (`peer.conn.WriteJSON`) happen without write deadlines. A slow or dead client blocks the write goroutine, eventually accumulating stuck goroutines. `gorilla/websocket` requires explicit write deadlines.

**Fix:** Set `peer.conn.SetWriteDeadline(time.Now().Add(5 * time.Second))` before each `WriteJSON` call.

### 1.7 Mesh: Re-Handshake on Every Operation (MEDIUM)

**File:** `internal/mesh/mesh.go:233-278`

`executeTask` calls `m.initialize(ctx, peer)` before every `tools/call`. MCP initialization is a full JSON-RPC handshake. For N broadcast operations to the same peer, this results in N handshakes instead of 1. No connection pooling or session caching.

**Fix:** Cache the initialized state per peer (e.g., `sync.Map` of `peer.URL → initialized`). Skip re-initialization if the peer was recently initialized (within 5 minutes). Or at minimum, add `initialized` bool to `Peer` struct.

### 1.8 Mesh: JSON-RPC ID Hardcoded to 1 (LOW)

**File:** `internal/mesh/mesh.go:368`

```go
ID: 1,
```

Every JSON-RPC request uses ID 1. If concurrent requests are in flight (Broadcast), responses could be mismatched. Currently mitigated because `call` is synchronous per-request, but if HTTP/2 pipelining is ever used, this breaks response correlation.

**Fix:** Use `atomic.Int64` counter for request IDs.

### 1.9 MCP Bridge Hooks: Parameter Name Mismatch — `session` vs `session_id` (HIGH)

**File:** `cmd/reasonix-hooks/main.go:119`

The `doReflect` handler sends `"session"` as the parameter key, but the memory server's `hindsight_reflect` handler expects `"session_id"`. This means the reflect command **always uses an empty session ID**, making it return all memories instead of session-scoped ones.

**Fix:** Change `"session"` to `"session_id"` in `doReflect`.

### 1.10 Bot Gateway: Race Condition in `/approve` Handler (MEDIUM)

**File:** `internal/bot/gateway.go:592-605`

The `/approve` HTTP handler reads `state.ctrl` outside the lock, then uses `ctrl.Approve()` after releasing the lock. Another goroutine could close the controller between the lock release and the `Approve()` call, causing a panic or nil dereference.

**Fix:** Copy the controller pointer while holding the lock, or call `Approrove()` under the lock.

### 1.11 Compressor: Unbounded Cache + SetTurn Data Race (MEDIUM)

**File:** `internal/compress/compress.go`

The `Compressor.cache` map grows without bound — over a long session with many unique tool outputs, it consumes unbounded memory. Additionally, `SetTurn()` writes the `turn` field without synchronization while `Compress()` reads it from another goroutine — data race.

**Fix:** Add cache eviction (LRU or max-size cap). Protect `turn` with `atomic.Int32` or include it in the mutex.

### 1.12 Collab Hub: `Start()` Returns Nil on Bind Failure (MEDIUM)

**File:** `internal/collab/collab.go`

`Hub.Start()` launches `ListenAndServe` in a goroutine and returns `nil` immediately. If the bind fails (port in use, permission denied), the error is only logged — the caller never knows the server didn't start.

**Fix:** Use `net.Listen()` first, then pass the listener to `Serve()`. Return any bind error to the caller.

### 1.13 Netclient: New HTTP Client Per Call — No Connection Pooling (MEDIUM)

**File:** `internal/netclient/netclient.go:56-61`

`DefaultClient()` creates a new `*http.Client` with `http.DefaultTransport` on every call. No connection reuse, no TLS session caching, no connection pooling. Every HTTP request creates a fresh transport.

**Fix:** Use `sync.Once` to create a shared client, or return a package-level default.

### 1.14 Publish: Panic on Empty Role String (LOW)

**File:** `internal/publish/publish.go:143-145`

```go
label = strings.ToUpper(role[:1]) + role[1:]
```

Panics if `role` is empty string. No guard for zero-length input.

**Fix:** Add `if role == "" { role = "unknown" }` before the transformation.

### 1.15 Hooks: Always Exits 0 — Masks All Errors (LOW)

**File:** `cmd/reasonix-hooks/main.go`

All error paths call `os.Exit(0)`. The hook runner never reports failure to the calling process, masking network errors, missing binaries, and invalid configurations.

**Fix:** Use `os.Exit(1)` on error paths.

## 2. Security Issues

### 2.1 No TLS for MCP HTTP Server

**File:** `pkg/mcputil/server.go:105-146`

`ServeHTTP` starts a plain `http.Server`. No TLS configuration. In production, MCP bridge and memory server would expose bearer-token-authenticated endpoints over plaintext HTTP. An attacker on the same network can sniff API keys.

**Fix:** Add `ServeHTTPSTLS` method accepting `tls.Config`, or document that a reverse proxy (nginx/caddy) should terminate TLS in front.

### 2.2 No CORS Headers on HTTP MCP Server

**File:** `pkg/mcputil/server.go:91-101, 107-117`

No CORS headers on `/mcp` or `/health` endpoints. Browser-based MCP clients (if any exist) will be blocked by same-origin policy. Minor for CLI clients, but limits future web integrations.

**Fix:** Add configurable CORS middleware in `ServeHTTP`.

### 2.3 MCP Bridge: Path Traversal in Skill File Access

**File:** `cmd/reasonix-mcpbridge/main.go:452-463`

`findSkillFile` constructs paths from user-controlled `name` parameter:

```go
path := filepath.Join(dir, name+".md")
```

If `name` is `"../../etc/passwd"`, `filepath.Join` resolves to `/etc/passwd.md` (or similar). `os.Stat` + `os.ReadFile` follow symlinks.

**Fix:** Validate `name` contains no path separators (`/`, `\`, `..`). Use `filepath.Base(name)` before joining.

### 2.4 Collab Hub: No Authentication on WebSocket (HIGH)

**File:** `internal/collab/collab.go`

Any WebSocket client can connect, subscribe to any session, and send steer commands. No token/auth validation.

**Fix:** Add auth middleware (query param token or first-message auth) to WebSocket upgrade handler.

### 2.5 Collab Hub: WebSocket CheckOrigin Always True — CSRF Vulnerability (HIGH)

**File:** `internal/collab/collab.go:110`

```go
upgrader websocket.Upgrader{CheckOrigin: func(r *http.Request) bool { return true }}
```

Any origin can connect. In production, this allows CSRF attacks where malicious sites proxy connections.

**Fix:** Validate `Origin` header against an allowlist of permitted origins.

### 2.6 MCP HTTP Server: No ReadHeaderTimeout — Slowloris Vulnerability (MEDIUM)

**File:** `pkg/mcputil/server.go:129-146`

`http.Server` created without `ReadHeaderTimeout` or `ReadTimeout`. Vulnerable to slowloris attacks — a client can hold connections open indefinitely, exhausting file descriptors.

**Fix:** Add `ReadHeaderTimeout: 10 * time.Second` and `ReadTimeout: 30 * time.Second`.

### 2.7 Memory Server: HTTP Binds to All Interfaces by Default (MEDIUM)

**File:** `cmd/reasonix-memoryserver/main.go:727`

`srv.ServeHTTP(":"+port, ...)` binds to `0.0.0.0`. The memory server exposes retain/recall/reflect endpoints — anyone on the network can read and modify memories.

**Fix:** Default to `127.0.0.1` binding. Add `--bind` flag for explicit configuration.

### 2.8 Marketplace: JWT Assertion Uses HS256 with Client Secret in Memory (LOW)

**File:** `internal/marketplace/lobehub_client.go:192-211`

JWT assertion uses HS256 with `client_secret` as signing key. The secret is stored in memory and could leak via memory dumps. No JWT claims validation on received tokens.

**Fix:** Consider RS256 for production. At minimum, validate `exp` and `iss` claims on received tokens.

## 3. Concurrency & Performance Issues

### 3.1 Memory Server: O(n) Full Scan on Every Recall/Search

**File:** `cmd/reasonix-memoryserver/main.go:343-418`

`Recall` iterates all entries for keyword matching. `SearchSimilar` computes cosine similarity against every entry. With 10K+ memories, each query scans 10K entries linearly. No indexing, no inverted index, no pre-filtering.

**Impact:** Degrades linearly. At 100K memories, each recall is a 100K-iteration scan holding an exclusive lock (because Recall mutates).

**Fix:** Add inverted index for tag/keyword lookups. Use SQLite's FTS5 for full-text search (already available since `sqlite_storage.go` exists). For vector search, use approximate nearest neighbor (ANN) instead of brute-force cosine.

### 3.2 Memory Server: Save on Every Write — Write Amplification

Every `Retain`, `Recall`, and `Tidy` call serializes the entire `memories.json` to disk. With 10K memories at ~1KB each, that's 10MB per write. Under heavy use (many retain/recall cycles), this becomes a bottleneck and risks data corruption on crash (partial write).

**Fix:** SQLite backend already exists — default to it. For file backend, use append-only write-ahead log (WAL) pattern instead of full rewrite. Or at minimum, batch writes with a debounced flush.

### 3.3 Compressor: SHA-256 on Every Tool Output

**File:** `internal/compress/compress.go:94-136`

Every `Compress()` call computes `sha256.Sum256` of the entire raw output. For large outputs (file reads, web fetches), this is expensive CPU work before any compression logic even starts.

**Fix:** Use a faster hash (xxhash, fnv-1a) for content-addressable caching. SHA-256 is overkill for dedup — you're not doing cryptography, just matching identical outputs.

### 3.4 Learn: Ring Buffer Eviction is O(n)

**File:** `internal/learn/learn.go:113-114`

```go
l.observations = l.observations[1:]
```

This creates a new slice header and copies the underlying array. At 200 capacity, this is fine. At 2000 (max), it's still negligible. But the pattern is inelegant — a proper ring buffer would be O(1).

**Fix:** Use `l.observations[l.head] = obs; l.head = (l.head + 1) % l.maxObs` ring buffer pattern. Low priority given max 2000 entries.

### 3.5 Learn: `detectPatterns` Runs on Every Observe Call

**File:** `internal/learn/learn.go:119`

Every `Observe()` call triggers `detectPatterns()`, which iterates all observations and builds pattern maps. At O(n) per observation, total pattern detection across a session is O(n²). For 200 observations, 40,000 iterations.

**Fix:** Defer pattern detection to `Patterns()` or `BuildReflectionPrompt()` call. No need to recompute on every turn.

### 3.6 Scheduler: Minute-by-Minute Cron Scan (LOW)

**File:** `internal/scheduler/scheduler.go:346-361`

`NextAfter` scans minute-by-minute up to 2 years. For `0 9 * * *` (daily at 9am), this scans up to 540 minutes (9 hours) to find next occurrence. For `0 0 1 1 *` (yearly), it scans up to 525,600 minutes. In practice, cron expressions are simple, but this is algorithmically poor.

**Fix:** Compute next fire time analytically. Standard cron algorithms (like `github.com/robfig/cron/v3`) do this in O(1) per field. Consider using a library instead of rolling your own parser.

## 4. API & Protocol Issues

### 4.1 MCP Bridge: `callDeepSeek` Hardcoded Model and Temperature

**File:** `cmd/reasonix-mcpbridge/main.go:296-309`

`callDeepSeek` hardcodes `"deepseek-v4-flash"` and `temperature: 0.3`. The `plan_task` and `orchestrate_task` tools always use DeepSeek regardless of what model the caller configured. This ignores the agent's configured model and provider.

**Fix:** Accept model/temperature from config or tool parameters. At minimum, read `DEEPSEEK_MODEL` env var (already partially done on line 296).

### 4.2 MCP Bridge: `orchestrateTask` Runs Arbitrary Subprocesses

**File:** `cmd/reasonix-mcpbridge/main.go:258-268`

`orchestrateTask` spawns `reasonix run` commands via `exec.CommandContext`. Each sub-task gets 5 minutes. If the decomposition produces many steps, this spawns N subprocesses with no resource limits. The `maxConcurrent = 3` semaphore limits parallelism, but there's no total timeout.

**Fix:** Add a context deadline for the entire orchestration (e.g., 15 minutes total). Add `cmd.SysProcAttr` with process group management to ensure cleanup on timeout.

### 4.3 MCP Memory Server: `limit` Type Mismatch

**File:** `cmd/reasonix-memoryserver/main.go:612-613`

```go
if l, ok := args["limit"].(float64); ok {
    limit = int(l)
```

JSON numbers unmarshal as `float64` in `map[string]any`. This is correct. But if a client sends `limit: "10"` (string), it silently defaults to 10 with no error. Should validate and return an error for wrong types.

### 4.4 mcputil: No Request Size Limit on HTTP Mode

**File:** `pkg/mcputil/server.go:92`

```go
body, err := io.ReadAll(r.Body)
```

No size limit. A malicious client can send a multi-GB body. The `mesh.call()` method limits to 10MB (`LimitReader`), but the MCP server endpoint doesn't.

**Fix:** Add `http.MaxBytesReader(w, r.Body, 10<<20)` before `ReadAll`.

### 4.5 mcputil: `handleCallTool` Ignores Unmarshal Error

**File:** `pkg/mcputil/server.go:189-196`

```go
if err := json.Unmarshal(req.Params, &call); err != nil {
    return s.ErrorResponse(req.ID, -32602, "Invalid params: "+err.Error())
}
```

The error is returned but `call` may be partially initialized. If `Params` is `null`, `call.Name` is empty string, and the handler proceeds with an empty tool name, producing a confusing "unknown tool" error. Should check for null/missing params first.

## 5. Architecture & Design Issues

### 5.1 No Graceful Shutdown in MCP Bridge (stdio mode)

**File:** `cmd/reasonix-mcpbridge/main.go:525-550`

The main function starts `srv.ServeStdio()` with no signal handling. If the parent process sends SIGTERM, `ServeStdio` just dies mid-request. The HTTP mode has graceful shutdown via `signal.Notify`, but stdio mode doesn't.

**Fix:** Wrap stdio mode in a signal handler similar to the memory server's HTTP mode.

### 5.2 Memory Server: File Backend Default Is Fragile

**File:** `cmd/reasonix-memoryserver/main.go:689-691`

Default backend is `file` (JSON file). This means all memories are loaded into RAM and rewritten on every mutation. For production use, SQLite is clearly superior, but it's not the default.

**Fix:** Default to `sqlite`. The `--backend` flag should default to `sqlite`, not `file`. File backend should be explicitly opt-in for development/testing.

### 5.3 Mesh: No Connection Pooling or Timeout Configuration

**File:** `internal/mesh/mesh.go:48,130`

`Peer.client` uses `netclient.DefaultClient()` which may or may not have timeouts configured. The `initialize` + `call` sequence makes 2-3 HTTP requests per operation with no connection reuse beyond what `http.Client` provides. For high-frequency mesh operations, this is wasteful.

**Fix:** Add configurable timeouts to `PeerConfig`. Consider HTTP/2 connection pooling or persistent connections.

### 5.4 Mesh: Broadcast Returns Partial Results on Error

**File:** `internal/mesh/mesh.go:162-186`

`Broadcast` never returns an error (only `nil`). If all peers fail, it returns an empty slice, which the caller must interpret as "no results." No way to distinguish "all peers timed out" from "no peers configured."

**Fix:** Return `(results, errors)` or add error metadata to `DelegationResult` for broadcast-level failures.

### 5.5 Compressor: No Max Size Limit

**File:** `internal/compress/compress.go:94`

`Compress` accepts arbitrarily large strings. SHA-256 + string manipulation on multi-MB outputs burns CPU and memory. No circuit breaker.

**Fix:** Add a size threshold (e.g., 1MB). Skip compression for outputs exceeding it.

### 5.6 Constitution System: No Validation on Load

**File:** `internal/constitution/` (referenced in AGENTS.md)

The constitution system loads `.reasonix/constitution.json` but there's no visible schema validation. Malformed constitution files could crash or silently produce wrong behavior.

**Fix:** Add JSON schema validation on load. Reject invalid constitutions early with clear error messages.

### 5.7 No Structured Logging in Mesh/Collab

Mesh and Collab use `log.Printf` (from Go stdlib) in some places and no logging at all in others. The rest of Reasonix uses `log/slog`. Inconsistent logging makes debugging harder.

**Fix:** Replace `log.Printf` with `slog.Info/slog.Error/slog.Warn` throughout mesh, collab, and scheduler packages.

## 7. Dependency & Build Issues

### 7.1 `go.mod` Missing Indirect Tags

Several direct imports are listed as `// indirect`:

```
github.com/google/uuid v1.6.0 // indirect
```

`uuid` is directly imported by `cmd/reasonix-memoryserver/main.go` (for embedding client). Running `go mod tidy` would fix this. Minor but indicates the module hasn't been tidied recently.

### 7.2 `modernc.org/sqlite` — CGO Dependency Risk

**File:** `go.mod:31`

`modernc.org/sqlite v1.52.0` is a pure-Go SQLite implementation. Good choice — avoids CGO. But it's a large dependency (compiles to ~15MB). The Dockerfile uses `CGO_ENABLED=0`, which works because modernc is pure-Go. Verify this consistently across all build targets.

### 7.3 Dockerfile: Hardcoded `GOARCH=amd64`

**File:** `Dockerfile:18-31`

All `go build` commands hardcode `GOARCH=amd64`. No multi-platform build (arm64 for Apple Silicon, arm64 for AWS Graviton). The goreleaser config likely handles this for releases, but the Dockerfile only produces amd64 images.

**Fix:** Use `--platform=$BUILDPLATFORM` with Docker buildx, or add arm64 targets.

### 7.4 No `.goreleaser.yaml` Validation for Hermes Binaries

The goreleaser config exists but should be verified to include all Hermes binaries (mcpbridge, memoryserver, bot, hooks, pr-review, e2ebench). Missing binaries from goreleaser = missing from releases.

### 7.5 Dockerfile: UID Mismatch

**File:** `Dockerfile:46`

```dockerfile
RUN mkdir -p /workspace && chown 65532:65532 /workspace
```

The `distroless/static-debian12:nonroot` user is UID 65534, not 65532. The `chown` grants ownership to UID 65532 which doesn't exist in the image. The workspace directory will be owned by a nonexistent user, causing permission errors at runtime.

**Fix:** Use `65534:65534` to match distroless's nonroot user, or add a `USER` directive with explicit UID.

### 7.6 Dockerfile: No `.dockerignore` Verification

`COPY . .` pulls the entire repo into the build context. Without a `.dockerignore` that excludes `.git`, `bin/`, `desktop/`, `node_modules/`, and test artifacts, the build context bloats and may leak secrets.

**Fix:** Add `.dockerignore` with explicit exclusions.

### 7.7 Dockerfile: No `HEALTHCHECK` or OCI Labels

No `HEALTHCHECK` instruction and no OCI image labels (`org.opencontainers.image.version`, etc.). Container orchestrators can't determine liveness.

**Fix:** Add `HEALTHCHECK CMD ["/usr/local/bin/reasonix", "--version"]` and OCI labels.

### 7.8 docker-compose.yml: API Keys in Environment Variables

`DEEPSEEK_API_KEY` passed as environment variable — visible via `docker inspect`. Should use Docker secrets or `.env` file with restricted permissions.

### 7.9 docker-compose.yml: No Version Pinning

`reasonix-hermes:latest` tag — no version pinning. `latest` can introduce breaking changes at any pull.

### 7.10 Helm Chart: Security Context Missing

No `runAsNonRoot`, `readOnlyRootFilesystem`, `allowPrivilegeEscalation: false`, or resource limits on containers. Pods run with default service account and full permissions.

### 7.11 Helm Chart: ConfigMap `config_version = 1`

Helm values template has `config_version = 1` while actual config uses `config_version = 2`. Deployed instances will use stale schema.

### 7.12 Helm Chart: Collab Port Rendered Unconditionally

Service template renders collab port regardless of `components.collab.enabled`. The `{{- if .Values.service.type }}` conditional is always true.

## 8. Documentation & Configuration Issues

### 8.1 `reasonix.toml` — Hardcoded Absolute Paths in Permissions (CRITICAL)

The committed `reasonix.toml` contains ~20 hardcoded `Bash(...)` allow rules with absolute paths like `/Users/alex.maksimchuk/projects/reasonix`. Anyone cloning the repo gets rules for your machine. This is a **security risk** (reveals directory structure) and **portability problem** (breaks on every other machine).

**Fix:** Remove all machine-specific allow rules from the committed config. Move them to a local override in `~/.config/reasonix/config.toml` (gitignored). Commit only the sanitized example.

### 8.2 `reasonix.example.toml` — Duplicate `price` Key

Already noted in AGENTS.md as a fixed bug (2026-07-06), but worth verifying the fix persists. Duplicate TOML keys cause silent override.

### 8.3 `reasonix.toml` vs `reasonix.example.toml` — Inconsistencies

- `bash_timeout_seconds`: 30 (actual) vs 120 (example) — users copying example will get different timeouts
- Config resolution path: `~/Library/Application Support/reasonix/config.toml` (macOS, in actual) vs `~/.config/reasonix/config.toml` (Linux, in example) — different paths, both valid per platform, but undocumented
- `config_version = 2` (actual) vs commented out (example) — example should document this field
- Provider `kind`: actual uses `ollamacloud` for all, example uses `openai`/`anthropic` — intentional (Hermes extension) but undocumented
- No `[network]` or `[desktop]` section in actual config (present in example)

### 8.4 CI Pipeline: `ci-hermes.yml` Tests Only 3 of 55 Packages

The Hermes CI workflow runs `go test` on only `./internal/config/ ./internal/agent/ ./internal/provider/` — **95% of the codebase is untested in CI**. Missing packages include bot, control, tool, plugin, memory, serve, sandbox, and all Hermes-specific additions (mesh, collab, scheduler, learn, compress, constitution).

**Fix:** Change to `go test -count=1 -race ./...` to test all packages. Add golangci-lint and govulncheck like the upstream CI.

### 8.5 CI Pipeline: Action Version Drift

- `sync-upstream.yml` uses `actions/checkout@v4` and `setup-go@v5` while other workflows use `@v6` and `@v6` respectively
- `ci-hermes.yml` uses Node 22 while upstream CI uses Node 24
- `pr-review.yml` also uses older action versions

**Fix:** Standardize all workflows to latest action versions.

### 8.6 `.golangci.yml` — Only 5 Linters Enabled

Currently: errcheck, govet, ineffassign, staticcheck, unused. Missing critical linters:
- `gosec` — security audit (hardcoded credentials, SQL injection, weak crypto)
- `gocritic` — code quality (dupImports, truncateCmp)
- `revive` — exported comments, package comments
- `goconst` — repeated string constants
- `nilerr` — nil error returns shadowed by nil values
- `sqlclosecheck` — unclosed SQL resources (relevant for sqliteStorage)

**Fix:** Add at minimum `gosec` and `gocritic`.

### 8.7 Missing API Documentation for Mesh/HTTP Endpoints

No OpenAPI/Swagger spec for the mesh HTTP endpoints or the collab WebSocket protocol. The JSON-RPC message format is only documented in code comments.

**Fix:** Add `docs/mesh-api.md` and `docs/collab-protocol.md` with request/response examples.

### 8.3 `REASONIX.md` — 51KB Design Doc

This is massive. It likely contains stale information mixed with current architecture. Should be split into focused documents (architecture, config reference, API reference).

### 8.4 Config Validation Gap

No config validation on startup. Invalid TOML values (wrong types, out-of-range numbers, unknown keys) silently use defaults. A typo in `reasonix.toml` like `enabled = "tru"` (string vs bool) would silently disable the feature.

**Fix:** Add config validation function that runs on startup and warns/errors on unknown keys, type mismatches, and out-of-range values.

## 11. Positive Observations

Well-designed aspects worth calling out:

1. **Clean separation of concerns** — MCP protocol handling (mcputil) is cleanly separated from business logic. Both mcpbridge and memoryserver reuse it.

2. **Constant-time auth comparison** — `httputil/auth.go` uses `subtle.ConstantTimeCompare`. Correct security practice.

3. **Content-addressable compression** — The compressor's safe-mode (preserving error output) is thoughtful. Most compression systems would happily compress stack traces.

4. **Constitutional pattern detection** — The `learn` package's trajectory detection and pattern naming is creative and useful.

5. **Multi-backend storage** — Memory server supports both file and SQLite backends. Clean `Storage` interface.

6. **Proper goroutine management** — Broadcast and Status use WaitGroups correctly. No leaked goroutines in the mesh package.

7. **Distrolress base image** — Docker runtime uses `distroless/static-debian12:nonroot`. Minimal attack surface.

8. **Council mode** — Well-structured judge pattern with structured JSON output and fallback to raw text. Practical adversarial analysis.

9. **Portable mode** — `REASONIX_PORTABLE` env var redirects all data paths. Clean USB-drive deployment story.

10. **Ring buffer for observations** — `learn.Learner` properly caps observations with eviction. Simple but effective.
